# Relay project instructions

Relay is an AI product for families. `master-handoff.md` records its product research, decisions, implementation state, and next steps. These instructions govern Codex project continuity; they do not describe a feature of Relay.

## Session start

1. At the beginning of every new Codex session, read `master-handoff.md` completely before starting development work.
2. Understand Relay's product vision, architecture, current implementation, decisions, and outstanding tasks. If architecture or implementation has not been established, record that accurately.
3. Inspect the actual codebase and project files to verify the documented state. Never assume the handoff is perfectly up to date; reconcile discrepancies before relying on it.

## During development

- Keep track of significant completed work and relevant files created or modified.
- Document important technical and architectural decisions, including their reasons.
- Record bugs, blockers, and unresolved questions.
- Keep outstanding tasks and next steps current.
- Update `master-handoff.md` after significant milestones.

## Before session end or context exhaustion

1. Update `master-handoff.md` with completed work and the exact current development state.
2. Document unfinished work, blockers, and the next recommended actions.
3. Preserve important historical decisions.
4. Verify the updated handoff against the actual codebase before claiming it is current.

## Handoff rules

- Treat `master-handoff.md` as the primary project continuity document.
- Preserve existing useful information. Keep research findings distinct from verified implementation facts and provisional ideas.
- Organize additions clearly. Remove outdated information only when it is safe to do so; do not blindly rewrite or truncate the document.
- Never claim something was implemented without verifying it in the project files or working product.
